# Спецификация

## Контекст / Проблема

Запросы на индивидуальные скидки в B2B-продажах сейчас согласуются через чаты и почту. Из-за этого нет единого места контроля, непонятны текущий статус, ответственный согласующий, условия решения, длительность согласования и причины отказа. Отдельный риск: менеджер может обещать клиенту скидку до подтверждения, а финансовый контроль затем отклоняет скидку. Источник: Вход, CR-01, CR-11.

## Бизнес-цель

- Все запросы на скидку доступны в одном месте. Источник: CR-01.
- Каждый запрос имеет видимый статус. Источник: CR-03.
- Время согласования сокращается за счет маршрутизации, SLA-индикации и уведомлений. Источник: CR-09, CR-10.
- Количество скидок без подтверждения снижается за счет явного процесса решений. Источник: CR-11.
- Менеджер получает результат и причину отказа или задержки для объяснения клиенту. Источник: CR-11, CR-15.

## Границы объема

- Внутри объема:
  - отдельный экран CRM с канбан-представлением запросов на скидку. Источник: Вход, CR-01, CR-03;
  - создание запроса на скидку менеджером продаж. Источник: Вход, CR-11;
  - отображение текущего статуса запроса. Источник: CR-03, CR-11;
  - принятие решения согласующими ролями. Источник: CR-02, CR-05, CR-06, CR-07;
  - отображение результата и причины отказа или одобрения менеджеру. Источник: CR-11, CR-15;
  - справочник причин отказа и одобрения. Источник: Лог уточнений: CL-01, CR-15;
  - SLA-подсветка карточки и уведомление при превышении срока ответа. Источник: CR-10;
  - журнал изменений как требование к прослеживаемости действий. Источник: Вход, CR-15;
  - техническая подготовка под будущую автоматическую рекомендацию скидки без обязательного рабочего механизма рекомендации. Источник: Лог уточнений: CL-05, CR-12.
- Вне объема текущего MVP:
  - аналитика по отказам. Источник: Лог уточнений: CL-01, CR-15;
  - дашборд руководителя. Источник: Лог уточнений: CL-01, CR-15;
  - экспорт в Excel. Источник: Лог уточнений: CL-01, CR-15;
  - интеграция с DWH. Источник: Лог уточнений: CL-01, CR-15;
  - Kafka-события как обязательный релизный scope. Источник: Лог уточнений: CL-01, CR-15;
  - API для мобильного приложения. Источник: Лог уточнений: CL-01, CR-15;
  - пользовательский интерфейс администратора CRM для настройки правил. Источник: Лог уточнений: CL-03, CR-14;
  - автоматическая отправка письма клиенту после одобрения до юридического подтверждения. Источник: Лог уточнений: CL-04, CR-13;
  - ML-модель, формула рекомендации, обязательное отображение рекомендации и автоотклонение скидок. Источник: Лог уточнений: CL-05, CR-12;
  - автоматическое применение скидки в коммерческом предложении как подтвержденное MVP-поведение. Источник: Вход, CR-13.

## Термины и определения

- Запрос на скидку: объект CRM, в котором менеджер просит согласовать индивидуальную скидку по сделке.
- Согласующий: роль, которая принимает решение на соответствующем этапе маршрута.
- SLA: срок ответа по запросу на скидку.
- VIP-клиент: клиент с признаком VIP в карточке запроса.
- Справочник причин: набор шаблонных причин отказа и одобрения, доступных согласующему при принятии решения.
- Базовая маржа: значение маржинальности сделки, используемое для финансовой оценки скидки; способ расчета при пустом значении CRM остается неблокирующим риском GAP-02.

## Акторы

- Менеджер продаж. Источник: CR-02.
- Руководитель отдела продаж. Источник: CR-02.
- Финансовый контролер. Источник: CR-02.
- Коммерческий директор. Источник: CR-02.
- Администратор CRM. Источник: CR-02.

## Пользовательские сценарии

- Основные:
  - Менеджер продаж создает запрос на скидку, заполняет данные сделки и отправляет запрос на согласование. Источник: CR-04, CR-11.
  - Согласующий видит запрос на своем этапе и принимает решение: одобрить или отклонить с причиной и комментарием. Источник: CR-02, CR-11, CR-15.
  - Менеджер продаж отслеживает статус запроса и видит итоговое решение с причиной отказа или одобрения. Источник: CR-03, CR-11, CR-15.
  - Система подсвечивает запрос красным и отправляет уведомление, если SLA превышен. Источник: CR-10.
- Альтернативные:
  - Для скидки от 5% до 12% запрос проходит финансовую проверку. Источник: CR-06.
  - Для скидки выше 12% запрос требует утверждения коммерческого директора. Источник: CR-07.
  - Для VIP-клиента применяется более короткий SLA. Источник: CR-09.
- Исключительные:
  - Если базовая маржа ниже порога, скидка не согласуется автоматически. Источник: CR-08.
  - Если базовая маржа отсутствует, автоматическое согласование требует обработки по правилу, отмеченному в GAP-02. Источник: CR-08, GAP-02.

## Функциональные требования

- FR-01: CRM должна предоставлять отдельный экран запросов на скидку с канбан-колонками по статусам из CR-03. Источник: CR-01, CR-03.
- FR-02: Менеджер продаж должен создавать запрос на скидку с данными карточки из CR-04. Источник: CR-04, CR-11.
- FR-03: Система должна сохранять статус запроса и отображать его менеджеру и согласующим. Источник: CR-03, CR-11.
- FR-04: Согласующие должны принимать решение по запросу с обязательной фиксацией результата и причины при отказе или одобрении. Источник: CR-11, CR-15.
- FR-05: Система должна маршрутизировать запрос по простой MVP-схеме процента скидки: до 5%, от 5% до 12%, выше 12%. Источник: CR-05, CR-06, CR-07, Лог уточнений: CL-02.
- FR-06: Система должна учитывать ограничение по марже: при марже ниже порога скидка не должна согласовываться автоматически. Источник: CR-08.
- FR-07: Система должна поддерживать более быстрый SLA для VIP-клиентов. Источник: CR-09.
- FR-08: При превышении SLA система должна подсветить запрос красным и отправить уведомление. Источник: CR-10.
- FR-09: Система должна фиксировать журнал изменений запроса, статусов, решений и комментариев. Источник: CR-15.
- FR-10: Система должна включать справочник причин отказа и одобрения для выбора согласующим. Источник: Лог уточнений: CL-01, CR-15.
- FR-11: Система должна предусмотреть техническую подготовку под будущую автоматическую рекомендацию скидки без обязательного ML, формулы, рабочей рекомендации или автоотклонения в MVP. Источник: Лог уточнений: CL-05, CR-12.
- FR-12: Правила согласования в MVP должны конфигурироваться технически через rule engine или аналогичный механизм без пользовательского интерфейса администратора CRM. Источник: Лог уточнений: CL-03, CR-14.
- FR-13: Система должна предоставить REST API `/discount-requests` согласно техническому предложению, если он нужен для CRM-модуля; API для мобильного приложения не входит в MVP. Источник: CR-14, Лог уточнений: CL-01.

## Валидационные правила

- Запрашиваемая скидка должна быть числовым значением в процентах. Источник: CR-04, CR-05, CR-06, CR-07.
- Запрос не может перейти в "Одобрено" или "Отклонено" без решения согласующего. Источник: CR-11.
- При отказе или одобрении должна быть выбрана причина из справочника либо заполнен комментарий согласующего по правилам формы. Источник: CR-15.
- Автоматическое согласование запрещено, если маржа ниже порога. Источник: CR-08.
- Обязательность ИНН, конкурента и файла КП остается неблокирующим риском GAP-01. Источник: CR-04, GAP-01.

## Бизнес-правила

- Для MVP используется простая маршрутизация по проценту скидки. Источник: Лог уточнений: CL-02.
- Скидка до 5% может быть согласована руководителем отдела продаж. Источник: CR-05.
- Скидка от 5% до 12% требует финансовой проверки. Источник: CR-06.
- Скидка выше 12% требует утверждения коммерческого директора. Источник: CR-07.
- Категория клиента, регион и маржинальность являются будущими факторами правил и не входят в MVP-маршрутизацию. Источник: Лог уточнений: CL-02, CR-16.
- Для VIP-клиентов согласование должно быть быстрее. Источник: CR-09.
- Если срок ответа превышен, запрос подсвечивается красным и отправляется уведомление. Источник: CR-10.

## Модель состояний / Переходы

- Начальное состояние: "Черновик". Источник: Вход, CR-03.
- Состояния:
  - "Черновик". Источник: Вход, CR-03.
  - "На согласовании у руководителя". Источник: CR-03.
  - "Финансовая проверка". Источник: CR-03.
  - "На утверждении у коммерческого директора". Источник: CR-03.
  - "Одобрено". Источник: CR-03.
  - "Отклонено". Источник: CR-03.
  - "Истек срок". Источник: CR-03.
- Переходы:
  - "Черновик" -> "На согласовании у руководителя". Источник: Вход, CR-03.
    - Инициатор: менеджер продаж.
    - Событие / условие: менеджер отправляет заполненный запрос.
    - Источник: CR-11.
  - "На согласовании у руководителя" -> "Одобрено"
    - Инициатор: руководитель отдела продаж.
    - Событие / условие: скидка до 5% и решение "одобрить".
    - Источник: CR-05.
  - "На согласовании у руководителя" -> "Финансовая проверка"
    - Инициатор: система или руководитель отдела продаж.
    - Событие / условие: скидка от 5% до 12% или требуется финансовая оценка.
    - Источник: CR-06.
  - "Финансовая проверка" -> "Одобрено"
    - Инициатор: финансовый контролер.
    - Событие / условие: финансовая проверка пройдена и коммерческий директор не требуется.
    - Источник: CR-06.
  - "Финансовая проверка" -> "На утверждении у коммерческого директора"
    - Инициатор: система или финансовый контролер.
    - Событие / условие: скидка выше 12% или требуется утверждение коммерческого директора.
    - Источник: CR-07.
  - "На утверждении у коммерческого директора" -> "Одобрено"
    - Инициатор: коммерческий директор.
    - Событие / условие: решение "одобрить".
    - Источник: CR-07, CR-11.
  - Любой статус согласования -> "Отклонено"
    - Инициатор: текущий согласующий.
    - Событие / условие: решение "отклонить" с причиной.
    - Источник: CR-11, CR-15.
  - Любой активный статус согласования -> "Истек срок"
    - Инициатор: система.
    - Событие / условие: превышен SLA.
    - Источник: CR-10.

## Ограничения

- Автоматическая отправка письма клиенту после одобрения не входит в MVP до юридического подтверждения. Источник: Лог уточнений: CL-04, CR-13.
- ML-модель, формула, обязательное отображение рекомендации и автоотклонение скидок не входят в MVP. Источник: Лог уточнений: CL-05, CR-12.
- При пустой базовой марже нельзя скрыто выполнять автоматическое согласование без определенного правила. Источник: CR-08, GAP-02.
- Пользовательский интерфейс администратора CRM для настройки правил не входит в MVP. Источник: Лог уточнений: CL-03, CR-14.
- Kafka, DWH, аналитика по отказам, дашборд руководителя, экспорт в Excel и API для мобильного приложения не входят в MVP. Источник: Лог уточнений: CL-01, CR-15.
