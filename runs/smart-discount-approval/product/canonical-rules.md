# Канонические правила

## Правило
ID: CR-01
Тип: цель
Формулировка: Все запросы на индивидуальную скидку должны быть видимы в одном месте в CRM.
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-02
Тип: роль
Формулировка: В процессе участвуют менеджер продаж, руководитель отдела продаж, финансовый контролер, коммерческий директор и администратор CRM.
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-03
Тип: состояние
Формулировка: Запрос на скидку проходит через состояния "Черновик", "На согласовании у руководителя", "Финансовая проверка", "На утверждении у коммерческого директора", "Одобрено", "Отклонено", "Истек срок".
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-04
Тип: данные
Формулировка: Карточка запроса должна поддерживать поля клиент, ИНН, сумма сделки, базовая маржа, запрашиваемая скидка, причина скидки, конкурент, файл коммерческого предложения, дата ожидаемого закрытия сделки, комментарий менеджера, комментарий согласующего, SLA, признак VIP-клиента.
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-05
Тип: бизнес-правило
Формулировка: Для MVP скидка до 5% может согласовываться руководителем отдела продаж.
Источник: Вход, Лог уточнений: CL-02
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-06
Тип: бизнес-правило
Формулировка: Для MVP скидка от 5% до 12% требует финансовой проверки.
Источник: Вход, Лог уточнений: CL-02
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-07
Тип: бизнес-правило
Формулировка: Для MVP скидка выше 12% требует утверждения коммерческим директором.
Источник: Вход, Лог уточнений: CL-02
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-08
Тип: ограничение
Формулировка: Если маржа ниже порога, скидку нельзя согласовать автоматически.
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории, Отчет о пробелах и рисках

## Правило
ID: CR-09
Тип: SLA
Формулировка: Для VIP-клиентов согласование должно быть быстрее, чем для обычных клиентов.
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории, Отчет о пробелах и рисках

## Правило
ID: CR-10
Тип: SLA
Формулировка: Если срок ответа превышен, запрос должен подсвечиваться красным и должно отправляться уведомление.
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-11
Тип: MVP
Формулировка: Минимальный объем включает создание запроса менеджером, отображение статуса, принятие решения согласующими и отображение результата с причиной отказа.
Источник: Вход
Использовать дальше: Спецификация, Пользовательские истории

## Правило
ID: CR-12
Тип: будущий объем
Формулировка: В MVP фиксируется только техническая подготовка под будущую автоматическую рекомендацию скидки; ML, формула, рабочая рекомендация и автоотклонение скидок не являются обязательным поведением MVP.
Источник: Вход, Лог уточнений: CL-05
Использовать дальше: Спецификация

## Правило
ID: CR-13
Тип: ограничение
Формулировка: Автоматическая отправка письма клиенту после одобрения остается вне MVP до юридического подтверждения.
Источник: Вход, Лог уточнений: CL-04
Использовать дальше: Спецификация, Отчет о пробелах и рисках

## Правило
ID: CR-14
Тип: реализация
Формулировка: Техническая команда предлагает микросервис discount-approval, PostgreSQL, Camunda, REST API /discount-requests, rule engine и UI на React Table; в MVP правила конфигурируются технически через rule engine или аналогичный механизм без пользовательского интерфейса администратора.
Источник: Вход, Лог уточнений: CL-03
Использовать дальше: Спецификация

## Правило
ID: CR-15
Тип: граница MVP
Формулировка: В MVP входит справочник причин отказа и одобрения; аналитика по отказам, дашборд руководителя, экспорт в Excel, DWH, Kafka и API для мобильного приложения находятся вне MVP.
Источник: Вход, Лог уточнений: CL-01
Использовать дальше: Спецификация, Пользовательские истории, Отчет о пробелах и рисках

## Правило
ID: CR-16
Тип: будущий объем
Формулировка: Категория клиента, регион и маржинальность фиксируются как будущие факторы правил, но не включаются в MVP-маршрутизацию.
Источник: Вход, Лог уточнений: CL-02
Использовать дальше: Спецификация, Отчет о пробелах и рисках
