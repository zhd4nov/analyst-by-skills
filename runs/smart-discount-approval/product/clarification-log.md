# Лог уточнений

## Запись
ID: CL-01
Этап: scope-finalizer-agent
Вопрос: Какие элементы из спорного списка CR-15 входят в первую версию: аналитика по отказам, шаблоны причин, дашборд руководителя, экспорт в Excel, интеграция с DWH, события в Kafka, API для мобильного приложения?
Почему задан: Нужно закрыть границу MVP по дополнительным пунктам, перечисленным продуктовым руководителем.
Ответ пользователя: В текущий MVP входят только шаблоны причин как справочник причин отказа/одобрения. Вне MVP: аналитика по отказам, дашборд руководителя, экспорт в Excel, DWH, Kafka, API для мобильного приложения.
Что закрыто или изменено: Закрыт GAP-06; справочник причин включен в MVP, остальные перечисленные элементы вынесены вне MVP.

## Запись
ID: CL-02
Этап: scope-finalizer-agent
Вопрос: Для первой версии подтверждаем простую маршрутизацию по процентам скидки или текущий scope должен учитывать категорию клиента, регион и маржинальность?
Почему задан: В требованиях был конфликт между простой схемой продаж и расширенными факторами финансового контроля.
Ответ пользователя: Для первой версии берется простая маршрутизация по процентам скидки. Категория клиента, регион и маржинальность фиксируются как будущий фактор правил, но не входят в MVP.
Что закрыто или изменено: Закрыт GAP-03; простая маршрутизация по процентам подтверждена для MVP, расширенные факторы вынесены в будущий объем.

## Запись
ID: CL-03
Этап: scope-finalizer-agent
Вопрос: Администрирование правил согласования входит в MVP как пользовательское действие администратора CRM или правила только технически конфигурируются через rule engine без пользовательского интерфейса администратора?
Почему задан: US-08 описывала пользовательское администрирование правил, но источник подтверждал только технический rule engine.
Ответ пользователя: Администрирование правил в CRM не входит в MVP как пользовательский сценарий администратора. В MVP правила конфигурируются технически через rule engine или аналогичный механизм без пользовательского интерфейса администратора.
Что закрыто или изменено: Пользовательская история администрирования правил исключена из MVP; техническая конфигурация rule engine сохранена как реализационное ограничение.

## Запись
ID: CL-05
Этап: scope-finalizer-agent
Вопрос: Автоматическая рекомендация скидки в MVP должна быть обязательным рабочим поведением или текущий scope ограничивается технической подготовкой?
Почему задан: В требованиях была неопределенность между ML/формулой, рекомендацией и автоотклонением скидок.
Ответ пользователя: Автоматическая рекомендация скидки в MVP не обязательна. В MVP фиксируется только техническая подготовка под будущую рекомендацию, без ML/формулы и без автоотклонения скидок.
Что закрыто или изменено: Закрыт GAP-05; обязательная рабочая рекомендация, ML/формула и автоотклонение исключены из MVP.
